*matlabserver.txt*   One Matlab session, kept warm   *matlabserver-plugin*

                                          *matlabserver* *plugin-matlabserver*
Keeps a Matlab session alive in the background and talks to it over a
loopback socket, so running something costs milliseconds instead of the five
seconds Matlab needs to start. Lives in plugin/matlabserver.vim,
autoload/matlabserver.vim and matlab/server.m.

1. Commands                                     |matlabserver-commands|
2. The session                                  |matlabserver-session|
3. :make and the quickfix list                  |matlabserver-make|
4. When it closes                               |matlabserver-idle|
5. Output                                       |matlabserver-output|
6. Settings                                     |matlabserver-settings|

==============================================================================
1. Commands                                            *matlabserver-commands*

                                                              *:MatlabStart*
:MatlabStart            Start the session. Takes a few seconds, once. Vim
                        does not block: carry on and use |:MatlabStatus| to
                        see when it is ready.

                                                               *:MatlabStop*
:MatlabStop             Ask the session to quit and shut it down. Also run
                        automatically when Vim exits.

                                                             *:MatlabStatus*
:MatlabStatus           Whether the session is up, the measured round trip,
                        the Matlab release, its current directory, and how
                        long it will sit idle before closing itself.

                                                                   *:Matlab*
:Matlab {command}       Evaluate {command} in the session. Short output is
                        echoed, longer output opens a window; see
                        |matlabserver-output|.

                                                                *:MatlabRun*
:MatlabRun              Write the current buffer and run it. Matlab is moved
                        to the file's directory first, so helper functions
                        sitting beside it resolve.

==============================================================================
2. The session                                          *matlabserver-session*

The session is its own Matlab process with its own workspace. It shares
nothing with a Matlab desktop you have open, and it does not stop you
opening one: an Individual licence lets the same user run several sessions
at once. This was measured, not assumed - one session was held open while a
second started, and both ran.

So keep the desktop for the debugger, where the GUI earns its keep, and use
this one for running things without waiting. Variables set by |:Matlab| are
not visible to the desktop and vice versa.

Round trips measured on this machine, against a five second cold start: >

    startup                          ~4 s   (once)
    :MatlabStatus round trip           8 ms
    A = magic(4); disp(A)            6.7 ms
    y = 2+2                          1.3 ms
    two 400x400 SVDs                  88 ms
<
The socket comes from Java's ServerSocket rather than `tcpserver`, which
needs the Instrument Control Toolbox; Matlab always ships a JVM. It binds
loopback only and refuses anything else, because it evaluates whatever it is
sent.

==============================================================================
3. :make and the quickfix list                             *matlabserver-make*

In a matlab or octave buffer |:make| runs the current file in the session and
puts anything that raised into the quickfix list, so |:clist|, |:cnext| and
|:cc| walk the error the usual way. after/ftplugin/matlab.vim selects
compiler/matlab.vim for this; nothing else has to be set up. >

    :make
    :clist
       1 helper.m:2: Undefined function 'nosuchfunction' for input ...
       2 bad.m:2: called from bad
<
The first :make of a Vim session starts Matlab and takes a couple of seconds.
Every one after that is about 0.2 s, nearly all of it Python's startup.

Three things happen before :make shells out, from a |QuickFixCmdPre| hook:

  - The buffer is written if it is modified. :make on a stale file is a trap,
    and Vim's own answer to it, 'autowrite', is a global setting this plugin
    should not turn on for you.

  - The session is started if it is not running, and waited for. :make is
    synchronous, so waiting is what you would expect; |g:matlabserver_start_timeout|
    caps it.

  - Vim's own connection is dropped. server.m serves one client at a time, so
    the socket has to be free for the program :make runs. The next |:Matlab|
    reconnects on its own.

'makeprg' runs matlab/mlmake.py, because :make goes through the shell and
cannot speak to the socket itself. The script only relays: server.m already
reports errors as `file:line: message`, which is what 'errorformat' reads, so
nothing parses Matlab output on the Vim side. Errors name the innermost frame
first, then each caller, so :cnext walks out of the stack.

Note for anyone editing compiler/matlab.vim: the paths there are quoted by
hand with forward slashes rather than through |shellescape()| and `%:p:S`.
With 'shell' set to bash and 'shellslash' off, shellescape() reads the
backslashes of a Windows path as escapes and drops them, turning
`C:\a b\c.py` into `"C:a bc.py"`.

==============================================================================
4. When it closes                                          *matlabserver-idle*

A forgotten session would hold several hundred megabytes for the rest of the
day, so it closes itself. It shuts down after |g:matlabserver_idle| seconds
with nothing to do, thirty minutes by default, and Vim reports that the
session exited the next time it looks.

The clock covers waiting for a client and waiting for a command from one. It
does not run while a command is being evaluated, so a long computation is
never cut short however long it takes.

The timeout is enforced inside server.m rather than by a Vim timer, so it
still fires if Vim is killed outright and never gets to clean up. Leaving
Vim normally shuts the session down through |VimLeavePre| as well, which
lets Matlab quit in its own time instead of being cut off.

==============================================================================
5. Output                                                *matlabserver-output*

Output of one or two lines is echoed on the status line. Anything longer, or
anything that raised, opens a split above the current window: read-only,
unlisted, wiped when closed, and reused by the next command.

q                       Close the output window.
K                       Look the name under the cursor up with |:MatlabDoc|.

Both this window and |matlabdoc|'s help window take the filetype "matlabout",
so ftplugin/matlabout.vim carries that behaviour once rather than each plugin
repeating it. It is a scratch buffer type, not a real file type, the same way
diredit and synexplore are.

Errors are reported as Matlab's message plus the frames from your own code.
The `evalc` and server.m frames that carry the command are dropped, as are
warning backtraces, the clickable `<a href="matlab:...">` markup Matlab
writes for its own desktop, and the backspaces it pads warning text with. >

    Error: Undefined function 'undefinedThing' for input arguments of
    type 'double'.
<
==============================================================================
6. Settings                                            *matlabserver-settings*

                                                       *g:matlabserver_port*
g:matlabserver_port     Loopback port to listen on. Default 51763.

                                                       *g:matlabserver_idle*
g:matlabserver_idle     Seconds of quiet before the session closes itself.
                        Default 1800, thirty minutes. See
                        |matlabserver-idle|.

                                                    *g:matlabserver_timeout*
g:matlabserver_timeout  How long to wait for a reply, in milliseconds.
                        Default 60000. Raise it if you run something slow
                        with |:MatlabRun|.

                                             *g:matlabserver_start_timeout*
g:matlabserver_start_timeout
                        How long |:make| waits for a session to come up, in
                        milliseconds. Default 30000.

                                                     *g:matlabserver_python*
g:matlabserver_python   The python that runs matlab/mlmake.py for |:make|.
                        Default "python".

g:matlabdoc_program     Which matlab.exe to run, shared with |matlabdoc|.
                        Documented at |g:matlabdoc_program|.
