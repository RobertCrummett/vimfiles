*prose.txt*   Proofread Typst and LaTeX: only the prose stands out   *prose-plugin*

                                         *prose* *plugin-prose* *typstprose*
While 'spell' is on in a window that shows a Typst or a LaTeX buffer,
everything that is not prose is drawn in one grey, so the text being
proofread is all that has colour. Lives in plugin/prose.vim and
autoload/prose.vim, with a scanner for each language in autoload/prose/, and
no program outside Vim.

1. Use                                          |prose-use|
2. Typst: what counts as code                   |prose-typst|
3. LaTeX: what counts as code                   |prose-tex|
4. Why not the syntax file                      |prose-why|
5. Speed                                        |prose-speed|
6. Limits                                       |prose-limits|

==============================================================================
1. Use                                                             *prose-use*
>
    :set spell          code goes grey, prose and spelling marks stay
    :set nospell        the usual colours are back
<
Nothing else is needed; `:set spell!` and anything that maps to it work the
same. It also applies when 'spell' is already set as the file opens.

Comments stay as the colorscheme has them. In `custom` that is the same grey
in bold, so a comment still stands out from the code around it.

The first `:set spell` in a buffer scans it, from the top, in the
background: a paper of 900 lines is grey in a quarter of a second, a book of
14000 lines takes some seconds to reach its end. After that the marks stay
on the text when 'spell' goes off, without a colour, so turning it on again
is immediate; only what was edited meanwhile is scanned again.

                                                                     *g:prose*
g:prose                 Set to 0 to never grey anything: >
                            let g:prose = 0
<
                                                               *g:prose_eager*
g:prose_eager           Set to 1 to have the marks made, unseen, as soon as a
                        Typst or LaTeX file is opened, and kept up to date
                        as it is edited. The first `:set spell` is then
                        immediate too, at the price of the scanning being
                        done whether or not 'spell' is ever set: >
                            let g:prose_eager = 1
<
                                                                *hl-proseCode*
proseCode               The highlight group of the grey. It links to
                        |hl-Comment| unless the colorscheme says otherwise;
                        `colors/custom.vim` links it to `customMuted`.

The grey is a text property (|text-properties|), which replaces the syntax
colour instead of mixing with it. |:SynCursor| lists it among the things
that colour the character under the cursor.

'spell' belongs to the window and the marks to the buffer. With one buffer
in two windows, one with 'spell' and one without, the window entered last
decides for both.

Vim also remembers 'spell' for each buffer a window has shown: `:set
nospell` typed in another buffer does not reach a file that was left with it
on, and that file is grey again when it is shown again.

==============================================================================
2. Typst: what counts as code                                    *prose-typst*

Grey:
  - `#` and the expression after it, as far as Typst reads it: `#name`,
    `#f(x)[y].z`, `#let x = 1 + 2` to the end of the line, `#if a {..} else
    {..}` to the last block, `#show x: it => { ... }` over as many lines as
    the block takes
  - math, `$ ... $`
  - raw text, between backticks
  - `<labels>` and `@references`

Not grey:
  - the text of paragraphs, headings, list items and emphasis, with their
    markers (`=`, `-`, `+`, `*`, `_`)
  - the same inside a content block `[...]` in code: the caption in
    `#figure(caption: [The potassium grid ...])` is prose, and only the
    brackets around it are grey
  - links written out as `https://...`
  - comments, which keep their own colour

==============================================================================
3. LaTeX: what counts as code                                      *prose-tex*

Grey:
  - the preamble, from `\documentclass` to `\begin{document}`, but for the
    text of `\title`, `\author`, `\date` and the like
  - a command, with the star after it: `\section`, `\centering`, `\\`
  - braces, `&` in a table, `#1`
  - math in all its forms: `$..$`, `$$..$$`, `\(..\)`, `\[..\]` and the
    environments (equation, align, gather, multline and the rest, starred or
    not), from `\begin` to `\end`
  - a label, a reference or a citation, whole: `\label{eqn:1}`,
    `\ref{fig:1}`, `\parencite[see][p.~5]{baranov-1957}`. Any command whose
    name ends in "ref" or has "cite" in it counts, so `\cref`, `\autoref`,
    `\citeauthor` and a `\figref` of your own do too
  - an argument that is a name, a length or a setting, for the commands in
    the table: `\includegraphics[width=3cm]{plot.pdf}`, `\vspace{1em}`,
    `\bibliography{refs}`, `\begin{tabular}{lcc}`,
    `\begin{subfigure}[b]{0.3\textwidth}`, the colour of
    `\textcolor{red}{...}` and the address of `\href{...}{...}`
  - an optional argument: a `[` right after a command, `\todo[inline]`,
    `\begin{figure}[ht!]`, `\\[2pt]`
  - verbatim text: `\verb|..|`, `\lstinline`, `\url{..}`, `\texttt{..}`, the
    verbatim, lstlisting and minted environments, and a tikzpicture

Not grey:
  - the text of the document, in or out of braces: what `\emph{..}`,
    `\footnote{..}`, `\caption{..}`, `\section{..}` and a command the table
    does not know are given is prose like the text around it
  - an optional argument that is text: `\item[Label]`, `\section[Short]`,
    `\caption[Short]`, `\begin{theorem}[Pythagoras]`
  - `\text{..}`, `\intertext{..}` and `\mbox{..}` in math
  - an escaped character, `\&`, `\%`, `\$`, and the accent in `caf\'e`
  - comments, which keep their own colour

                                                                *prose-tex-table*
What a command takes is in a table at the top of autoload/prose/tex.vim, one
letter for each argument in turn: >
    call s:Table(s:cmds, 'cc', 'setlength addtolength setcounter ...')
<makes both arguments of `\setlength{\parindent}{0pt}` code. A command of
your own whose argument is not prose goes there, on the line with the
letters that fit it; the comment above the table says what each letter
means. A command that is not in the table has its `[...]` as code and its
`{...}` as prose.

after/syntax/tex.vim takes its rules for arguments from the same table, so
that Vim checks the spelling of exactly what is left white: what is grey has
no spelling marks, and "a4paper", "htbp" or the key of a citation is no
mistake. Without 'spell' the same rules give LaTeX the colours of Typst:
commands lavender, references and citations hot pink, math one light purple
from delimiter to delimiter, verbatim text light pink, the titles of
sections bold and underlined, and the arguments that are code plain.

==============================================================================
4. Why not the syntax file                                         *prose-why*

Greying the syntax groups of code was tried first, for Typst, and could not
be made consistent. The bundled syntax finds code with regular expressions.
On a 922 line paper it took 1211 characters of prose for code, on 38 lines,
nearly all of it the text of content blocks inside calls; and it missed the
code on 6 lines, such as what follows the colon in >
    #show figure.where(kind: "subfigure"): set figure(supplement: "Figure")
<and the body of a `#show x: it => context {` that runs over several lines.

So the code is found by a scanner of its own. For Typst it follows Typst's
lexer and parser (typst-syntax 0.15) for the part that settles where code
starts and stops. It was checked character by character against that parser
on that paper, on a book of 14000 lines (166000 characters of code), on
twenty package source files and on thirty documents of edge cases, valid
and not, with no difference.

LaTeX has no grammar to check against: what an argument is depends on the
command. Its scanner goes by the rules of |prose-tex|, and was checked
against Vim's spell checking instead, both ways, on a manuscript of 600
lines and on files of constructs: no spelling mark falls on grey, and with
every word of prose replaced by a misspelling, every one of them is marked.

Spell checking itself still goes by the syntax file. In Typst, where that
takes code for prose, a word in it can be flagged, and shows as a spelling
mark on grey. Strings in code are not spell checked (after/syntax/typst.vim):
they are mostly file names, and "figures/potassium.png" would flag "png".

==============================================================================
5. Speed                                                         *prose-speed*

Typing must not wait for this, so:

  - Only what an edit may have changed is scanned again: from the last line
    above it where a scan can start, to the first line below it where the
    new scan and the old agree. In Typst a scan can start, and stop, at any
    line that begins in running text or between the delimiters of a call;
    in LaTeX at any line. For a change in a paragraph, a caption or a table
    cell that is the line itself.
  - Scanning runs from a timer, a moment after a change, never while a key
    is being handled, and in goes of at most 8 milliseconds or 250 lines,
    between which Vim takes the keys typed meanwhile.
  - What cannot be cut up (see |prose-limits|) is given up after a time
    limit and tried again with twice the limit, but only once the buffer
    has been left alone for six times as long.
  - The marks are left alone while text that was typed is still waiting to
    be drawn. Vim keeps one range of changed lines between two redraws and
    parses the syntax of all of it again; a character typed at the end of a
    long file and marks changed near its top, drawn together, cost a third
    of a second there.
  - In a LaTeX file of more than 4000 lines, marks for lines above every
    window are not put on the text one go at a time, but all at once when
    the scan reaches a window or ends. Marks changed above a window make
    Vim look for the syntax at its top again, which with the bundled way
    of syncing (see |prose-limits|) takes 50 ms whatever changed: once is
    not noticed, after every go it was.
  - In LaTeX, what is typed and not yet closed does not reach far: braces
    in the text of the document are not counted, and a `$` or a `\ref{`
    left open ends with the paragraph, as it does for TeX.

Measured in the Windows console. On a 922 line Typst paper, per change: 0.3
ms in a paragraph, 4 ms inside a sixty line call. On a 628 line LaTeX
manuscript: 0.6 ms per change, 80 ms for all of it. Typing at the end of a
long file while its first scan was still running, a key every 30 ms and
every 120 ms, no key was lost and the longest wait between two keys was:

                                   every 30 ms    every 120 ms
    without the plugin                 33             128
    Typst, 13826 lines                 64             140
    LaTeX,  2936 lines                 38             140
    LaTeX, 12746 lines                 46             143

Two things that would have been simpler are not done, because both lose
typed keys when called from a timer in the Windows console: `getchar(1)`,
to see whether a key is waiting, and `:redraw`.

==============================================================================
6. Limits                                                       *prose-limits*

Both:
- Enter typed inside a grey stretch leaves its mark in two parts, which Vim
  holds for one text property over two lines. Vim 9.2 does not keep such a
  pair in order: Enter, Enter, Backspace there gave internal errors (E340,
  E685, E967) and took the rest of the line away until an undo. So the two
  parts are made marks of their own the moment a line is split, also while
  'spell' is off and the marks are not seen. That needs the third argument
  of |listener_add()|; in a Vim without it the marks are scanned again
  after every change instead, seen or not, which leaves only keys that
  come in one run (a macro) in danger.

Typst:
- A statement is scanned in one piece, as is an equation: the body of
  `#let f(x) = { ... }`, of `#show x: it => { ... }`, the arguments of
  `#set page(...)`. That is about 0.3 ms a line, each time something in it
  changes: a hundred line function takes 30 ms, after a pause in the typing.
- Typst counts open `[` afresh inside emphasis, headings and list items, so
  a bracket opened in one and closed outside it pairs up differently there.
  Here every `[` in a content block pairs with the next free `]`.
- Non-ASCII letters count as identifier characters and the usual blocks of
  non-ASCII punctuation do not. Typst uses Unicode's XID classes, which
  differ for some symbols.
- The scanner follows Typst 0.15. A later version that changes where an
  expression ends needs the change made in autoload/prose/typst.vim.
- More than about forty levels of nesting are left as the syntax file
  colours them.
- The bundled syntax file synchronises from the start of the file, so the
  first jump to the end of a 14000 line file takes Vim half a second, with
  or without this plugin.

LaTeX:
- The table is the commands of LaTeX itself and of the common packages. A
  command it does not know, with a name or a length for an argument, has
  that argument taken for prose: add it to the table (|prose-tex-table|).
- A macro defined in the document is not looked at: what `\newcommand`
  makes of its arguments is not known, so they are prose.
- An optional argument that is text is seen only when its `]` is on the
  same line.
- A line of more than 10000 bytes is not looked at, and is left as the
  syntax file has it. A line cannot be scanned in parts, and the time for
  one grows with the square of its length: 30 ms at 5000 bytes.
- A comment between a command and its argument ends the command: in >
      \includegraphics[width=3cm]% the plot
        {plot.pdf}
< the file name is prose. Vim's syntax cannot follow an argument past a
  comment, and the two are kept the same.
- Only a file that Vim takes for LaTeX is handled ('filetype' is "tex").
  The vimrc sets `g:tex_flavor` to "latex" for that: without it a chapter
  in a file of its own, with no `\documentclass` at its top, is taken for
  plain TeX.
- Such a chapter is prose from its first line.
- The syntax of a file of up to 4000 lines is worked out from its first
  line (after/syntax/tex.vim), so the colours and the spelling marks are
  right wherever the file is opened. That costs 0.13 ms for each line above
  the window, once. A longer file keeps the bundled way, going back 50 to
  200 lines: opened in the middle of a long listing, preamble or equation,
  it can show that as text until the window has been moved there from
  above.
